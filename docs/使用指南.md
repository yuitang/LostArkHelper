# 命运方舟助手四端使用指南

- 适用版本：`v0.3.4`
- 活动接口版本：`2611`
- 更新日期：2026-11-08

命运方舟助手用于处理「方舟最佳搭档」活动中的每日签到和任务奖励领取。服务器版、Windows 本地版和 Linux 本地版提供完整网页工作台；iPhone 版是一个直接请求官方接口的快捷指令。

本文说明如何使用这四种版本、如何录入游戏用户信息，以及各端当前能够实现和不能实现的功能。

助手只会领取活动接口明确返回为可领取、且已经收录参数的任务奖励。它不会代替玩家登录游戏、刷副本、组队、累计签到或查看活动规则，也不会绕过官方活动条件。

## 一、先选择适合自己的一台设备

| 使用端 | 是否需要助手账号 | 运行方式 | 最适合的情况 |
| --- | --- | --- | --- |
| 服务器版 | 需要注册、登录 | 服务器持续运行，多用户数据隔离 | 希望手机、平板和电脑都能打开，且不依赖自己的电脑开机 |
| Windows 本地版 | 不需要 | 当前 Windows 用户下的后台服务和网页工作台 | 主玩游戏的是 Windows 10/11 电脑，电脑会定期开机 |
| Linux 本地版 | 不需要 | 当前 Linux 用户下的后台服务，可安装为 systemd 用户服务 | 使用 Linux 桌面、家庭服务器或无桌面 Linux 主机 |
| iPhone 快捷指令 | 不需要 | 运行一次，按顺序查询签到和任务 | 不想部署服务，接受手动运行或由“个人自动化”触发 |

当前线上服务器入口：

<https://lostarkhelper.dpdns.org>

所有正式文件统一从 GitHub Release 下载：

<https://github.com/youboRepo/LostArkHelper/releases/tag/v0.3.4>

## 二、录入游戏用户信息前的准备

四端录入游戏用户信息的方式相同：粘贴官方 App 提供的完整活动链接，让助手自动解析 `token`、QQ 授权信息、区服和角色参数。正常导入不需要手工填写 Cookie、`token`、角色 ID 或服务器 ID。

请按以下步骤获取链接：

1. 在手机上的官方「命运方舟助手」App 登录 QQ 游戏账号。
2. 在 App 内切换到准备自动处理的正确角色。
3. 打开能够分享的官方活动页面。当前项目使用过「师徒结伴第 4 期」等带完整登录参数的链接。
4. 选择分享或复制链接，复制整条链接的全部内容。
5. 把整条链接粘贴到网页版的“账号管理 → 导入我的 token”，或 iPhone 快捷指令首次运行的输入框。

“完整参数”指的是整条链接已经包含登录凭据和角色信息。助手会在本地或自己的服务器后端解析这些参数，用户不需要逐个查找字段。

可以导入的网页链接需要满足以下条件：

- 使用 HTTPS。
- 域名是 `lostark.qq.com` 或 `bbs.lostark.qq.com`。
- 使用已经支持的 QQ 登录方式。
- 链接中包含唯一且完整的登录、应用和角色字段。

普通邀请链接如果只有好友 ID、没有登录凭据和角色字段，不能用于导入。遇到“链接缺少参数”“登录字段异常”时，应回到官方 App 重新复制完整活动链接，不要凭猜测手工补值。

活动链接等同于登录密码：

- 不要截图公开分享。
- 不要发到群聊、论坛或公开笔记。
- 不要写入 GitHub Issue、提交记录或日志附件。
- 凭据过期后重新获取链接，旧链接会失效。

## 三、所有网页版通用的首次流程

服务器、Windows 和 Linux 的界面基本相同，建议首次使用时按以下顺序操作：

1. 进入“账号管理”，点击“导入我的 token”。
2. 粘贴完整活动链接，点击“验证并保存”。
3. 保存成功后回到“总览”，点击“刷新状态”。
4. 核对页面显示的区服、角色，以及是否已签到和当前任务状态。
5. 点击“立即执行一次”，先完成一次手动验证。
6. 打开“运行记录”，确认签到结果、领取明细和失败原因。
7. 确认手动执行正常后，再进入“定时设置”，开启自动计划。

“立即执行一次”不会修改已经保存的定时计划。它只按当前状态立即查询，并在需要时签到和领取已完成的收录任务。

网页中的三个手动入口含义如下：

| 按钮 | 会做什么 |
| --- | --- |
| 每日签到 | 先查询签到状态；已签到则跳过，未签到才提交签到 |
| 领取任务奖励 | 查询当前任务，只领取状态可领取且在收录范围内的奖励 |
| 立即执行一次 | 完成签到检查，并继续领取当前已完成的收录任务奖励 |

## 四、服务器版

服务器版适合长期运行。每位用户拥有独立的助手账号、游戏凭据、定时计划和运行记录。

### 1. 注册和登录

1. 打开 <https://lostarkhelper.dpdns.org>。
2. 切换到“注册”，创建自己的助手账号。
3. 用户名使用 3–32 位字母、数字或下划线，不区分大小写。
4. 密码使用 12–128 个字符。
5. 注册完成后重新登录。

助手账号和 QQ 游戏账号是两层不同账号：

- 助手账号只用于登录网页和隔离每位用户的数据。
- QQ 游戏账号通过活动链接导入。
- 助手不会要求输入 QQ 密码。

登录会话通常保持约 7 天。当前没有网页自助找回密码功能，请妥善保管密码；忘记后需要联系服务器管理员处理。

### 2. 导入游戏账号

登录后进入“账号管理 → 导入我的 token”，粘贴完整活动链接。保存后先刷新总览并核对角色。

已有凭据时：

1. 再次进入“账号管理”。
2. 点击“更新我的 token”。
3. 粘贴同一账号、同一角色的新活动链接。
4. 勾选“确认更新我当前游戏账号和角色的登录凭据”。
5. 点击“验证并保存”。

网页只允许更新同一游戏账号和角色的登录凭据。需要处理另一个 QQ 账号或角色时，请注册另一个助手账号，不要在旧角色上强行覆盖。服务器扫码授权仍处于“待接入”状态。

### 3. 签到、领奖和定时

服务器版支持：

- 查看每日签到状态。
- 查看每日、每周和活动任务进度。
- 未签到时自动签到并查询确认。
- 领取 `status=1` 且任务 ID 已收录的唯一任务。
- 签到后重新查询，继续领取因此解锁的累计签到奖励。
- 每小时指定分钟执行，或每天指定多个时间执行。
- 保存下次执行时间和分页查看历史记录。

所有时间按北京时间（UTC+8）。新注册用户的定时任务默认关闭，首次手动执行验证正常后再开启。

当前线上服务器由系统服务持续调度。服务器在计划时间停机时，过期时间不会补跑；恢复后等待下一个计划时间。

### 4. 自行部署服务器

自行部署服务器的用户可从 Release 下载 `LostArkHelper-Server-v0.3.4.tar.gz`。部署需要 Python 3.9+、systemd，以及 HTTPS 反向代理或 Tunnel。

服务默认只监听 `127.0.0.1:18745`。建议把程序和网页放在 `/opt/lostark-dashboard`，把持久化用户状态放在 `/var/lib/ark-dashboard`；不要在升级时覆盖状态目录。公网域名必须通过 `ARK_PUBLIC_ORIGIN` 与反向代理正确配置。

首次初始化账号的用户名通常为 `ark`，初始密码由服务器私有 `panel.key` 生成。真实密码只应保存在服务器上，不要写入本指南或公开仓库。

完整部署、权限修正、状态备份和环境变量说明见 [服务器版 README](../server/README.md)。

## 五、Windows 本地版

### 1. 下载和启动

支持 Windows 10/11 x64。

1. 从 Release 下载 `LostArkHelper-Windows-x64-v0.3.4.zip`。
2. 把 ZIP 完整解压到一个固定目录。
3. 保留 `LostArkHelper.exe`、`_internal` 文件夹和 `VERSION` 文件。
4. 双击 `LostArkHelper.exe`。
5. 默认浏览器会自动打开本地工作台。

不要只复制 exe。发行版使用目录模式，运行时依赖同一目录中的 `_internal` 和网页资源。用户不需要安装 Python 或 Node.js。

本地版不需要注册助手账号，也不要求输入密码登录网页。启动器会打开一个仅限本机使用的随机访问地址。

### 2. 导入和手动验证

进入“账号管理 → 导入我的 token”，粘贴完整活动链接。保存后刷新总览，核对角色，再使用“立即执行一次”。

本地版与服务器版相同，只允许在后续更新凭据时覆盖同一游戏账号和角色。更换角色时应先安全停止服务并备份数据目录，再使用独立数据目录或全新的本地数据目录。

### 3. 后台运行、停止和自启

程序启动后保持后台运行：

- 关闭网页不会停止签到和定时任务。
- 再次双击 `LostArkHelper.exe` 会重新打开已有实例的工作台。
- 不需要一直保留终端窗口。
- 工作台不可访问时，重新双击启动器通常会打开当前实例链接。

进入“定时设置 → 启动设置”：

- 开启“登录 Windows 后自动启动”，可在当前用户登录后自动启动后台服务。
- 该启动项使用当前 Windows 用户的注册表，不需要管理员权限。
- 自启后默认只运行后台，不自动弹出浏览器。
- 关闭“自动启动”不会停止当前已经运行的实例。
- 移动程序目录后，请先停止服务，再关闭并重新开启自启，让注册表指向新路径。

安全停止：进入“定时设置 → 启动设置”，点击“停止本地服务”。程序会等待已经开始的操作结束。

### 4. 更新和数据

进入“定时设置 → 版本更新”：

1. 点击“检查更新”。
2. 只有 GitHub 正式 Release 才会被识别。
3. 发现新版后点击“下载并更新”并确认。
4. 程序会校验压缩包和 SHA256，退出旧进程，替换程序目录并启动新版。
5. 更新后再次双击 `LostArkHelper.exe` 打开新工作台。

更新只替换程序，不覆盖用户数据。旧程序目录会保留为同级的 `.previous` 目录。

Windows 数据目录：

```text
%LOCALAPPDATA%\LostArkHelper
```

主要文件包括：

- `credentials.dpapi`：由当前 Windows 用户 DPAPI 加密的游戏凭据。
- `automation.sqlite3`：定时计划和执行历史。
- `pending-operation.json`：尚未确认结果的游戏操作标记。
- `service.log`：脱敏启动日志。

升级会保留这些文件。DPAPI 与当前 Windows 用户绑定，换用户或重装系统后通常需要重新导入活动链接。

## 六、Linux 本地版

### 1. 系统要求

当前成品适用于 Ubuntu 22.04/24.04 x86_64 及兼容 glibc 2.35+ 的 Linux。

不支持：

- ARM 设备。
- Alpine 或其他 musl 系统。
- Windows WSL 中的其他发行版，除非其环境与上述条件兼容。

### 2. 下载、启动和停止

1. 下载 `LostArkHelper-Linux-x64-v0.3.4.tar.gz`。
2. 解压后进入目录。
3. 运行启动脚本。

```sh
tar -xzf LostArkHelper-Linux-x64-v0.3.4.tar.gz
cd LostArkHelper-Linux-x64-v0.3.4
./start.sh
```

启动脚本会把服务放到后台，并输出一条包含本次随机会话密钥的工作台链接。关闭终端或网页不会停止服务。

常用命令：

```sh
# 重新获取当前实例的工作台链接
./open-workbench.sh

# 安全停止服务
./stop.sh
```

不要公开带 `key=` 的工作台链接。服务每次启动都会生成新的会话密钥。

### 3. 导入、签到和定时

打开工作台后，使用“账号管理 → 导入我的 token”粘贴完整活动链接。刷新总览核对角色，手动执行一次，然后进入“定时设置”开启计划。

Linux 本地版的签到、领奖、历史记录、定时规则和凭据覆盖限制与 Windows 相同。

### 4. 登录后自动启动

如果系统支持 `systemd --user`，在解压目录运行：

```sh
./install-user-service.sh
./open-workbench.sh
```

查看运行状态：

```sh
systemctl --user status lostark-helper.service
journalctl --user -u lostark-helper.service
```

关闭自启并停止用户服务：

```sh
./install-user-service.sh --disable
```

默认情况下，用户服务在用户登录后启动。需要退出登录后继续运行，可在管理员授权下执行：

```sh
sudo loginctl enable-linger 用户名
```

移动程序目录后，需要在解压目录重新运行 `./install-user-service.sh`。

### 5. 无桌面 Linux

程序仍只监听 `127.0.0.1`。在自己的电脑上建立 SSH 本地端口转发：

```sh
ssh -N -L 18745:127.0.0.1:18745 用户名@Linux主机地址
```

保持 SSH 连接，然后打开 Linux 上 `./open-workbench.sh` 输出的链接。若实际端口不是 `18745`，SSH 命令和浏览器地址都要改为实际端口。

### 6. 更新和数据

Linux 本地版同样可在“定时设置 → 版本更新”检查和安装 GitHub 正式版。更新后旧会话失效，运行 `./open-workbench.sh` 获取新链接；systemd 用户服务仍指向原目录。

数据目录：

```text
${XDG_DATA_HOME:-~/.local/share}/LostArkHelper
```

目录权限通常为 `700`：

- `credentials.enc`：Fernet 加密后的游戏凭据。
- `credentials.key`：本机解密密钥，权限 `600`。
- `automation.sqlite3`：计划和执行历史。
- `pending-operation.json`：待确认操作标记。
- `service.log`：启动日志。

密钥和密文保存在同一用户目录，可以降低单独泄露密文的风险，但不能抵御同一 Linux 用户、root 或整个目录被复制后的访问。备份时应把整个数据目录当作敏感信息处理。

## 七、iPhone 快捷指令

### 1. 下载和导入

在 iPhone 上下载：

```text
LostArkHelper-iPhone-v0.3.4.shortcut
```

使用系统“快捷指令”App 打开并添加到快捷指令库。快捷指令在手机上直接访问腾讯官方活动接口，不依赖服务器或电脑。

### 2. 首次运行和后续运行

首次运行：

1. 在官方 App 登录 QQ 游戏账号并选择角色。
2. 复制完整活动链接。
3. 手动运行“LostArkHelper”。
4. 在提示框中粘贴整条链接。
5. 允许快捷指令访问网络和所需的 iCloud 文件。

校验成功后，链接保存在：

```text
iCloud Drive/Shortcuts/lostark-local-link.txt
```

以后运行快捷指令会直接读取保存的链接，不再要求输入文本或单独填写每个请求参数。

一次正常执行会：

1. 查询今天是否签到。
2. 未签到时提交签到，并重新查询确认。
3. 查询最新任务列表。
4. 只处理状态为可领取且在任务白名单中的奖励。
5. 每次领取前后重新查询。
6. 结果无法确认时立即停止并提示，不在本次运行中继续提交。

### 3. 更新失效凭据

链接过期或更换角色后：

1. 删除 `iCloud Drive/Shortcuts/lostark-local-link.txt`。
2. 重新运行快捷指令。
3. 粘贴新的完整活动链接。

也可以先在“文件”App 的 iCloud Drive `Shortcuts` 文件夹中查找该文件。快捷指令保存的是活动登录链接，属于敏感信息，应保护 iCloud 账号和设备锁屏。

### 4. 自动运行的限制

可以在“快捷指令 → 自动化”中创建个人自动化来运行它，但需要了解：

- iOS 可能要求解锁、确认或仅在前台执行。
- 系统可能因省电、后台策略或网络状态推迟运行。
- 快捷指令不是常驻后台服务。
- 多次触发重叠时可能同时运行，导致结果不可确认。

需要可靠定时执行时，优先使用服务器版、Windows 本地版或 Linux 本地版。

### 5. 快捷指令没有的能力

快捷指令版不提供网页工作台，不保存网页式执行历史，也不提供后台自启和可编辑定时计划。它不会与服务器或本地版共享操作锁，因此同一角色启用其他自动计划时不要再次运行快捷指令。

如果旧版出现“请为此操作的每个参数选取值”，先升级到当前 `v0.3.4` 快捷指令。旧版动作存在已修复的类型兼容问题。

## 八、当前能自动处理的任务

当前活动版本为 `2611`，四端白名单均为任务 ID `1–13`：

| ID | 任务 | 接入与验证说明 |
| ---: | --- | --- |
| 1 | 登录游戏 | 已接入现有领取映射 |
| 2 | 完成 1 次星辰护卫 | 已接入现有领取接口 |
| 3 | 通关 1 次卡杰洛斯副本 | 已接入现有领取接口 |
| 4 | 通关 2 次影子副本 | 已接入现有领取接口 |
| 5 | 通关 5 次混沌地牢或库尔赞前线 | 已接入现有领取接口 |
| 6 | 通关 1 次极焰的沙漏 | 参数按统一接口推断，尚无逐项成功抓包验证 |
| 7 | 累计签到 7 天 | 参数按统一接口推断，尚无逐项成功抓包验证 |
| 8 | 累计签到 14 天 | 参数按统一接口推断，尚无逐项成功抓包验证 |
| 9 | 累计签到 21 天 | 参数按统一接口推断，尚无逐项成功抓包验证 |
| 10 | 累计签到 28 天 | 参数按统一接口推断，尚无逐项成功抓包验证 |
| 11 | 首次查看活动规则 | 参数按统一接口推断，尚无逐项成功抓包验证 |
| 12 | 首次成功组建 4 人小队 | 已补入抓取到的任务领取流程 |
| 13 | 小队登录游戏（4/4） | 已补入抓取到的任务领取流程 |

任务 `6–11` 已按用户要求接入候选领取范围，但不能把“代码已接入”理解为“每个账号都已经真实领奖验证”。程序仍会在每次提交前要求对应任务唯一且状态为可领取，提交后必须查询确认。

助手不负责完成任务本身。例如，任务要求通关副本时，仍需玩家先在游戏内完成副本；任务要求查看活动规则或组建四人小队时，也需要先在官方活动或游戏中满足条件。

任务状态通常按以下方式显示：

- `status=0`：未完成。
- `status=1`：已完成、可以领取。
- `status=2`：已完成或已领取。
- `status=3`：已结束。

活动任务列表里的分类 `type` 与领取接口里的参数 `type` 含义不同。助手使用收录后的领取参数，不会直接把任务分类当作领取参数。实测表明领取参数恒为 `1`：每日任务（分类 `type=1`）与每周任务（分类 `type=2`）都用同一个值提交成功，二者不受任务分类影响。

## 九、签到与领奖执行规则

一次完整执行会遵守以下顺序：

1. 查询签到状态。
2. 已签到则跳过；未签到才提交签到。
3. 签到提交后再次查询，确认状态已经变为已签到。
4. 查询最新任务列表。
5. 只筛选 `status=1`、任务 ID 唯一且已在支持列表中的任务。
6. 每领取一个任务前再次查询，确认仍可领取。
7. 领取后再次查询，确认状态变为 `status=2`。
8. 状态无法确认时停止后续提交，并保留待确认标记。

签到成功后会重新查询任务，因此本次签到刚解锁的累计签到奖励也可能在同一次执行中领取。

以下情况会被跳过：

- 任务尚未完成。
- 任务已经领取。
- 任务 ID 不在当前白名单。
- 同一任务 ID 在列表中不唯一。
- 查询结果格式异常。
- 活动累计类任务（如「在活动中累计签到 7/14/21/28 天」）在定时执行中不自动提交，需要在面板手动领取；自动执行覆盖每日与每周任务。
- 同一任务被服务端连续明确拒绝两次后冷却 6 小时再试一次（成功后计数清零），既避免反复试错触发风控，也不永久放弃后来才变成可领取的任务。

领奖返回「查询任务信息失败」、但该任务始终显示可领取时，通常是活动 `token` 已失效：查询接口不校验这个参数，领奖接口会校验，所以状态查得到、奖励领不了。重新导入一次账号的活动链接（用角色本人的 QQ 登录活动页复制）即可恢复，不需要改区服或任务参数。

## 十、定时设置和执行时间

服务器、Windows 和 Linux 提供两种计划：

- 每小时执行：设置每小时的第几分钟，范围为 0–59。
- 每天执行：使用 24 小时制填写一个或多个 `HH:MM`，用逗号分隔，最多 24 个。

示例：

```text
09:00, 18:30
```

所有时间均为北京时间（UTC+8）。保存后会显示下一次计划执行时间。

计划执行还依赖服务和设备状态：

- 计划默认关闭，需要用户主动启用。
- Windows 必须保持程序运行并登录当前用户；Linux 必须保持服务运行，未启用 linger 时也需要用户保持登录。
- 服务器系统服务必须正常运行。
- 休眠、关机或断网期间无法执行。
- 错过的时间不会逐次补跑。
- 本地版恢复后会合并错过的多个时间槽，只按最近一次计划执行一次。
- 同一游戏角色不要配置多个平台计划。

## 十一、数据保存与备份

| 使用端 | 游戏凭据位置 | 加密方式 |
| --- | --- | --- |
| 服务器 | 每位助手用户独立的服务器状态目录 | 服务器文件权限隔离，公网链路使用 HTTPS |
| Windows | `%LOCALAPPDATA%\LostArkHelper\credentials.dpapi` | 当前 Windows 用户 DPAPI |
| Linux | `${XDG_DATA_HOME:-~/.local/share}/LostArkHelper/credentials.enc` | Fernet，密钥在同目录单独保存 |
| iPhone | `iCloud Drive/Shortcuts/lostark-local-link.txt` | 受 iCloud 和设备安全保护，但文件本身是完整链接 |

备份注意事项：

- Windows/Linux 的网页更新不会覆盖用户数据目录。
- 备份 Windows/Linux 数据目录时，应保护其中的凭据、密钥和数据库。
- 服务器管理员备份 `/var/lib/ark-dashboard` 时应限制访问权限。
- 不要只复制 Linux 的 `credentials.enc` 而遗漏 `credentials.key`，否则密文无法解密。
- 凭据失效时重新导入同一账号和角色的新链接，不需要删除计划或历史。

### 更换游戏账号或角色

网页版的安全设计只允许重新导入同一 `user_id`、`openid` 和角色 ID 的新 token。需要切换到另一个游戏账号或角色时：

- 服务器版：为另一个角色注册新的助手账号；原助手账号继续保留对应角色数据。
- Windows：先安全停止服务，把 `%LOCALAPPDATA%\LostArkHelper` 备份或改名，再启动程序并导入新链接。此操作会得到一套新的空白计划和历史。
- Linux：如果启用了用户服务，先运行 `./install-user-service.sh --disable`；否则运行 `./stop.sh`。再把 `${XDG_DATA_HOME:-~/.local/share}/LostArkHelper` 备份或改名，重新启动并导入新链接。
- iPhone：删除 `lostark-local-link.txt`，重新运行快捷指令并粘贴新链接。

希望同时保留多个角色时，优先使用不同的助手账号、操作系统用户或设备。不要通过手工修改数据库或凭据文件绕过角色校验。

## 十二、更新四端版本

| 使用端 | 推荐更新方式 |
| --- | --- |
| 服务器自部署版 | 备份状态目录和程序，按下一次 Release 的服务器部署说明替换并重启 |
| Windows | “定时设置 → 版本更新 → 检查更新 → 下载并更新” |
| Linux | “定时设置 → 版本更新 → 检查更新 → 下载并更新”，或手动替换解压目录 |
| iPhone | 从新 Release 下载 `.shortcut`，重新导入快捷指令 |

Windows/Linux 网页更新具有以下保护：

- 只安装 GitHub 正式 Release。
- 校验发布清单、压缩包和每个文件的 SHA256。
- 拒绝降级和路径异常的安装包。
- 存在待确认游戏操作时拒绝更新。
- 更新期间持有操作锁，等待已经开始的操作结束，并暂停新的游戏操作。
- 替换失败时保留或恢复旧程序。
- 用户凭据、计划和历史保存在独立数据目录中。

源码运行模式不能通过网页更新替换源码，需要使用 Git 或手动下载。`v0.2.0` 本地版需要先手动升级一次到带更新入口的版本。

## 十三、常见问题

### 1. 提示“分享链接无效”

重新从官方 App 复制整条链接。确认：

- 链接来自受支持的官方域名。
- 当前已登录 QQ 游戏账号。
- 已选择具体角色。
- 复制时没有只截取部分查询参数。
- 使用的是带登录字段的活动链接，而不是普通邀请链接。

### 2. 提示“登录字段异常：token”或接口查询失败

通常表示链接缺少字段、字段被截断、复制了旧链接，或登录凭据已经过期。

处理方式：

1. 在官方 App 重新登录并选择角色。
2. 重新复制完整活动链接。
3. 网页版勾选确认更新，重新导入。
4. iPhone 删除已保存的 `lostark-local-link.txt` 后重跑。

### 3. 已经有 token，为什么还要勾选确认

这是防止误覆盖现有角色的保护。更新前必须确认新链接仍然属于同一游戏账号和角色。当前界面不支持通过凭据更新直接切换到另一个角色。

### 4. 页面有任务，但助手没有领取

依次检查：

- 任务是否显示为“可领取”，即 `status=1`。
- 任务 ID 是否在 `1–13` 白名单中。
- 游戏中是否真的完成了任务。
- 同一任务 ID 是否在接口结果中重复。
- 运行记录是否显示未知 ID、状态变化或接口错误。

助手不会为了领取奖励而伪造任务完成状态。

### 5. 为什么任务 6–11 有时仍可能失败

这些任务使用与现有任务相同的统一领奖接口推断参数，还没有逐项真实领奖抓包。官方接口如果改变参数、拒绝请求或无法完成提交后状态确认，程序会停止并记录原因。

### 6. 网页打不开或本机链接失效

Windows：

1. 再次双击 `LostArkHelper.exe`。
2. 等待浏览器自动打开新链接。
3. 仍不可用时，检查数据目录中的 `service.log`。

Linux：

```sh
./start.sh
./open-workbench.sh
```

本机服务每次启动都会生成新的随机会话链接，旧链接在服务重启后失效。

### 7. 到达时间后没有执行

检查：

- “启用定时任务”是否已经勾选并保存。
- Windows/Linux 服务是否仍在后台运行。
- 电脑是否休眠、关机或未登录用户。
- 服务器服务是否正常运行。
- 当前是否还有另一个操作占用锁。
- 运行记录中是否显示“其他操作正在执行，本次已跳过”。

### 8. 提示“上次提交的结果仍未确认”

这表示签到或某笔奖励提交后，官方状态没有查询确认，并不一定是 token 过期。v0.3.2 起，服务器、Windows 和 Linux 可以通过更新 token 恢复：

1. 在官方 App 获取当前游戏账号、当前角色的新活动分享链接。
2. 进入“账号管理 → 更新我的 token”，粘贴完整链接并勾选确认更新。
3. QQ 登录有效性校验通过并成功保存后，助手自动解除该账号的待确认限制，无需手工删除文件或联系管理员。
4. 点击“立即执行一次”或等待下一次定时执行。助手会先重新查询官方状态，已签到、已领取的项目会跳过。

导入失败、账号或角色不匹配、凭据保存失败时，原待确认记录仍保留。保存 token 本身不会立即签到或领奖。如果官方再次拒绝操作或结果仍无法确认，助手会再次停止并提示更新 token。iPhone 无跨次运行的待确认文件，更新凭据请删除保存的链接文件后重新运行。

分享链接参数名已兼容大小写，例如 `accType=qc` 与 `acctype=qc` 均可导入；token 等参数值保持原样。v0.3.3 起，同名参数（包含不同大小写的写法）重复且值相同时可导入，值冲突时拒绝导入。

### 已完成游戏任务，却显示未完成或没有领奖

先确认导入的链接来自刚登录的官方 App，而不是以前保存的链接。官方任务接口可能在 QQ access token 过期时仍返回“成功”，但将登录游戏、讨伐星辰护卫等任务标成未完成；这不能说明游戏任务没有完成。

v0.3.4 起，四端在执行前增加 QQ 官方登录校验。凭据失效会明确提示在账号管理更新 token，校验网络异常则提示稍后重试；两种情况都不会用失真的任务状态继续执行。服务器、Windows、Linux 在导入链接时也会校验，过期链接不会保存成功。更新凭据不会代替你完成游戏内任务。

iPhone 出现过期提示时，删除 `iCloud Drive/Shortcuts/lostark-local-link.txt`，重新打开官方 App 获取当前角色的新链接，再运行快捷指令。单人“登录游戏”与“小队登录游戏(3/4)”是不同任务，小队人数不足时后者仍可显示未完成。

### 9. Windows/Linux 网页更新失败

检查能否访问 GitHub、正式 Release 是否包含当前平台文件，以及是否存在待确认游戏操作。更新失败时不要删除 `.previous` 目录。网络恢复后重新点击“检查更新”，仍无法处理时再下载对应 Release 手动替换。

### 10. Linux 用户服务启动失败

先停止手动后台实例：

```sh
./stop.sh
```

再重新安装用户服务并查看日志：

```sh
./install-user-service.sh
systemctl --user status lostark-helper.service
journalctl --user -u lostark-helper.service
```

### 11. 忘记服务器版密码怎么办

当前没有网页自助找回。请联系服务器管理员处理，不要尝试多次登录触发限流。

## 十四、目前不支持的操作

当前版本不支持：

- 在服务器网页直接扫码登录 QQ。
- 手工生成或猜测活动登录参数。
- 代替玩家完成副本、星辰护卫、组队、累计签到或活动规则查看。
- 自动领取未知任务 ID。
- 在同一网页账号中直接切换另一个游戏角色。
- 在服务器、Windows、Linux 和 iPhone 之间共享操作锁。
- 在 iPhone 快捷指令中提供可靠的后台常驻调度。
- 通过网页更新服务器版的源码和 systemd 部署。

活动接口带有版本号。当前只适配 `2611`；活动结束后官方可能更换版本、任务 ID、状态码或登录字段，助手需要重新抓包、审核白名单并同步四端配置。

## 十五、最短上手清单

服务器版：

1. 注册并登录。
2. 账号管理粘贴完整活动链接。
3. 刷新总览核对角色。
4. 立即执行一次并查看运行记录。
5. 开启定时任务。

Windows：

1. 完整解压，双击 `LostArkHelper.exe`。
2. 导入完整活动链接。
3. 手动执行一次。
4. 开启定时和“登录 Windows 后自动启动”。

Linux：

1. 解压，运行 `./start.sh`。
2. 导入完整活动链接。
3. 手动执行一次。
4. 开启定时，并按需运行 `./install-user-service.sh`。

iPhone：

1. 导入 `.shortcut`。
2. 首次运行粘贴完整活动链接。
3. 以后手动运行，或创建个人自动化。
4. 凭据过期时删除保存文件并重新粘贴链接。

无论使用哪一端，都请记住两条规则：**完整活动链接不能公开分享；同一条游戏角色只选择一个端开启自动计划。**
